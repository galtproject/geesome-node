# GeeSome Node v0.4.7 — release candidate

Prepared from stable `master` at `ac6059d1` (promotion PR #1370), compared
with `v0.4.6`. Tracking issue: #1371. Publication remains pending the final
metadata merge, release tag and verified local Docker publication.

## Changes

- Add an opt-in public tar.gz archive of an uploader's content or generated
  static site. The background queue pins the archive in IPFS and stores the
  original/archive CID mapping. Public lookup and download use the original CID.
  Ownership and scoped-key write permissions are checked before creation and
  again when the job executes.
- Static-site publication accepts `options.archive: true`, completes rendering
  independently of archive compression, and includes a top-right download
  control with waiting, retry and ready states. Existing immutable sites must
  be republished to receive the control. Archives include local UnixFS files
  and directories; external resources referenced by HTML are not downloaded.
- Restrict private-group, post, category, RSS and associated content reads to
  authorized creators, members or administrators. Clients relying on anonymous
  reads of private groups must now authenticate; public-group reads remain public.
- Add batch async-operation lookup and fix streamed multipart handling.
- Deliver Docker images by exact source commit, with prepared-runtime checks,
  persisted image selection, safe preparation before restart and retained
  previous-image selection. Registry failure permits local build fallback in
  auto mode. See [Docker delivery](../docker-images.md).
- Refresh locked dependencies, including markdown-it, Handlebars, sharp, axios,
  URI/address parsing and HTTP support libraries.

## Upgrade and compatibility

1. Back up PostgreSQL and retain the previous deployment/image and persistent
   data paths. Rehearse on a restored database before production rollout.
2. From a clean stable checkout on the server, run `npm run docker-upgrade`.
   The wrapper selects the matching published image or builds locally before
   restarting. Do not prune caches first. Use the deployment-aware
   `npm run docker-compose -- ...` wrapper for later stack operations.
3. Confirm model sync/migrations, API readiness, authenticated private-group
   access, media delivery, site publication and public archive download.
4. Configure the node's canonical public API URL correctly for generated-site
   downloads. Archive creation is explicit public publication: anyone knowing
   the original CID can download it, including an archive of a private upload.

There are no new migration files relative to `v0.4.6`. The new `contentArchives`
table and its indexes are created by model sync. Existing data is not backfilled
into archives. Normal migration chains still run during an upgrade.

Microwave Girls `main` at `1cbb1f34` includes publication integration commit
`8ddff608`: the Media BFF, membership worker and standalone Generation gateway
request background archiving. No Microwave Girls release/version bump is needed.
Visitors download through public GET endpoints without receiving an API token.

Rollback requires the previous image/source and a compatible database or the
paired pre-upgrade backup. Selecting `previous-image` only rolls back application
code; it does not undo database changes. Do not blindly run migration `down`.

## Final publication

The user merges the release metadata PR into `master`. Then tag that exact
stable commit `v0.4.7`, run local `docker-publish` for `linux/amd64` with
`GEESOME_RELEASE_TAG=v0.4.7`, verify both immutable SHA and version-alias registry
digests, and publish the GitHub release with those results. No CI publishes the
image. Synchronize the release metadata back to `dev` through normal PR flow.

Restored-production database rehearsal and server deployment are not included
in this release-preparation check. Evolving encrypted chat remains subject to
its existing limitations; this release does not certify completed E2EE.
